Found it, at least at EL2: it's the CoreSight CTCU. Since "hamoa: enable ETR
and CTCU devices" (8017f8fa34, in 7.3), the 14" never reaches CX collapse in
s2idle. Same 7.3 kernel, one 2-minute nap each:

| device tree | cxsd/ddr |
|---|---|
| 7.3's own | 0 % (5 naps) |
| 7.2's | 97.1 % |
| 7.3's, all coresight nodes disabled | 98.4 % |
| 7.3's, only `ctcu@10001000` disabled | 97.0 % |

With the CTCU off, the `qdss` clock (from `aoss_qmp`) shows enable count 0
while awake with the other coresight drivers loaded, so the CTCU is what
keeps QDSS voted on, and AOSS won't drop CX while it is. I haven't pinned
down which reference stays held (its driver enables the clock with
devm_clk_get_optional_enabled() and also toggles it from runtime PM;
unloading it warns about unbalanced disables). For now I disable the node
in the 14" DTS:

```
&{/soc@0/ctcu@10001000} {
	status = "disabled";
};
```

Worth a try at EL1 together with the timer fix: if `apss` counts but
`cxsd` doesn't, this is likely the same blocker.
